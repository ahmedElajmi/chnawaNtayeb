Bibliothèque de composants (prête pour le CMS)

Chaque composant est défini une seule fois (assets/components.js), stylé une seule fois (assets/components.css), alimenté par une source de données unique (assets/data.js) et placé n'importe où par un bloc { "c": nom, "props": {…} }. Cette page est elle-même générée depuis le registre : elle ne peut pas diverger du code.

Contrat d'un composant (pour le moteur CMS)

  • Nom stable en kebab-case (recipe-card) — c'est la clé enregistrée dans les pages.
  • Props typées et documentées (nom, type, défaut, rôle) — le CMS en tire son formulaire d'édition ; jamais de texte ou de donnée en dur dans le composant.
  • Données lues par identifiant (recette, étal, catégorie) depuis la source unique — jamais recopiées dans la page.
  • Textes par clé de traduction (4 langues), RTL géré par le composant.
  • État partagé explicite (filtres, planning) : plusieurs composants se coordonnent sans se connaître.
  • Imbrication : un conteneur (panel) accepte n'importe quel autre bloc ; la feuille de filtres réutilise filter-sentence, category-rail et ingredient-filter sans copie.
  • Implémentation React : un composant = un fichier src/features/…/X.tsx avec le même nom et les mêmes props ; le registre devient une table { nom → composant } utilisée par le rendu des pages CMS.
